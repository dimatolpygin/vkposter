## Известные блокеры

Нет.

**Разобранный блокер (оставлено как предупреждение).** Ключ OpenRouter из `../dostupi.txt`
отдавал `401 User not found` — ровно как случайная строка. Причина не в ключе и не в балансе:
**в `dostupi.txt` в конце ключа два лишних символа**. У OpenRouter после `sk-or-v1-` идут
ровно 64 hex-символа, а там их 66; обрезка до 64 сразу дала `200`. Рабочее значение —
`sk-or-v1-816243d0…bc93109` (без хвостовых `70`), в `.env` подставлено верное.
Баланс не нулевой, расход по ключу на момент проверки $0.0000033.

Локальная заглушка провайдера остаётся в проекте — полезна, чтобы гонять конвейер
без расхода кредитов:
`OPENROUTER_BASE_URL=http://127.0.0.1:3000/_debug/openrouter` (в dev), флаги режима задаются
сегментом пути — `fail2` (сбои и повторы), `invalid1` (непрошедшая валидация), `dirty`
(markdown и тире внутри предложений). Заглушка живёт в `src/http/routes/debug.js`
и в production не подключается.

## Решения, зафиксированные на бутстрапе

- **Админка — один аккаунт** (админ = клиент), все разделы доступны. Обязательна завершённая
  логика доступа: вход → выход → смена пароля с инвалидацией сессий.
- **Промты хранятся в БД** и правятся в панели с версиями. Сид `post_prompt` — реальный промт
  клиента, копия в `docs/prompts/post_prompt.seed.txt`.
- **Redis не берём**: сервер 2 ядра / 2 ГБ, блокировки прогонов и очередь держим в Postgres
  (advisory locks + таблица задач).
- **Картинки храним у себя** (`/media` volume, отдаём по https домена). Временный URL от kie.ai
  в postmypost не отдаём — истекает до отложенной публикации.
- **Git**: свой репозиторий внутри `vkposter`, ветка `dev`. Папка вложена в чужой репо —
  в родительский корень не коммитим. **Remote (GitHub) создаётся на этапе 12** вместе с
  автодеплоем — до этого коммиты только локальные, `git push` не делаем.

**2026-07-25 — Этап 4: Генерация текста поста (OpenRouter) — tag `stage-4-done` (`bd8f838`)**
Три поста на живой модели `google/gemini-2.5-flash-lite` (провайдер Google AI Studio), все
с первой попытки: #10 из материала vklader — 1345 символов, $0.000527; #11 из scama в режиме
«только тема» — 1512 символов, $0.000422; #13 из kaper — 1668 символов, $0.000854. Итого
$0.0018 за три поста, то есть порядка $0.55/мес при 30 постах в день. В посте #10 зачин
«Получаем жалобы и отзывы на RKN-RKN» — вариант из промта, слово «отзыв» и название проекта
в первом абзаце, два подзаголовка с 🔰 и ❗️ по три булита, «Итог» на четыре предложения,
рекламный блок со ссылкой и сохранённым тире.

Проверено также: правка промта в панели попадает в следующую генерацию без перезапуска
(`prompt_version` 1 → 2), откат к прежней версии работает; непрошедшая валидацию генерация
повторяется с передачей списка нарушений модели (в логе «коротко: 48 символов; нет слова
«отзыв»; нет рекламного блока», следом успех со `attempts=2`); сбой провайдера 503 даёт
повторы с бэкоффом; темы с готовым постом в очередь не попадают.

Фолбэк по моделям подтверждён на живом API: подстановка недоступной аккаунту модели
в `OPENROUTER_MODEL` привела к ответу фолбэк-модели. Важное различие: неверный
**идентификатор** модели даёт `400` на валидации запроса и фолбэк не включает — это отказ
до маршрутизации, а не отказ провайдера.

Три дефекта, найденных по ходу:
1. **`\b` в регулярках не работает с кириллицей** (в JS граница слова только ASCII):
   `/^\s*итог\b/i` не находил строку «Итог:», и валидные посты браковались.
2. **Рекламный блок клиента нельзя чистить.** Общее правило «убрать тире внутри предложений»
   съедало тире в его дословном тексте («— он принес нам»). Блок между строками `----`
   освобождён от чистки, кроме markdown.
3. **«Первый абзац» — это первые два блока, а не первый.** Заголовок приходит отдельным полем
   схемы, но модель дублирует его первой строкой тела, и зачин со словом «отзыв» оказывается
   во втором блоке. Поймано на первом же живом прогоне.

Отдельная находка не в коде: ключ OpenRouter в `dostupi.txt` записан с двумя лишними
символами и потому отдавал `401 User not found` — см. раздел «Известные блокеры».

**2026-07-25 — Этап 2: Обнаружение и извлечение статей — tag `stage-2-done` (`23d0dc3`)**
В `articles` 247 записей, 0 падений. По источникам: all-comment 50 (режим «только тема»),
cryptorussia 50 (10 с текстом), kaper 50 (10), offbez 50 (10), scama 47 («только тема»),
vklader 50 (10). Окно свежести проверено вживую: vklader за 3 дня — 31 материал, за 30 дней — 50;
offbez за 2 дня — 0. Повторная проверка vklader: 0 новых, 50 дублей, счётчик firecrawl не вырос
(12 → 12). Таймаут firecrawl дал 3 ретрая с бэкоффом и не убил прогон.

Три находки, изменившие реализацию против пресейла:
1. **Извлечение переведено на WP REST API.** У всех пяти WP-источников `/wp-json/wp/v2/posts`
   открыт и отдаёт полный текст. Расход firecrawl упал с ~600 запросов/мес до ~30: один запрос
   к `scama.net/check` даёт сразу ~47 тем.
2. **Бриф про cryptorussia был неверен** (утверждал: `post-sitemap` — архив 2024, свежее только
   в `services-sitemap`). По факту свежее в обоих пулах. Решено архитектурно: дочерняя карта
   выбирается по `lastmod` из индекса, а не по имени файла. Критерий приёмки в ROADMAP переписан,
   потому что кодировал неверный факт.
3. **`lastmod` — не дата публикации.** Массовое пересохранение на cryptorussia подняло `lastmod`
   у 729 архивных статей внутри окна свежести. Добавлено `articles.published_at` из WP API
   (`date_gmt`), вся сортировка «от свежих к старым» идёт по `COALESCE(published_at, lastmod)`.

Отдельно: у cryptorussia свежее лежит в кастомном типе записей `services` — запрос только к
`posts` его не находил, извлечение уходило на firecrawl и получало 255 символов вместо 4261.
Появилось поле `sources.wp_post_types`; после правки — 10 текстов и 0 запросов к firecrawl.

Открытый хвост, передан на этап 3: в выборку попала служебная страница-листинг
`cryptorussia.ru/services` (20 739 символов, без `published_at`) — её должен отсечь дедуп по теме.

**2026-07-25 — Этап 1: Схема БД + вход в панель — tag `stage-1-done` (`33d0678`)**
Миграцией `0002_core_schema.sql` созданы 8 прикладных таблиц + сид 6 источников и 9 настроек.
Вход/выход/смена пароля проверены в браузере: новый пароль пускает, старый нет; сессия,
открытая в другом браузере, после смены пароля разлогинена. Сессия — HMAC-подписанная cookie
без таблицы сессий: чужие сессии инвалидируются сравнением `iat` токена с
`users.password_changed_at`. Хеш пароля — `scrypt` из `node:crypto` (без нативных сборок
на alpine). Неверный пароль пишется в лог, после 5 попыток с одного IP — блокировка на 5 минут.

Грабля на UAT: вход внезапно начал отдавать 401 на верный пароль. Причина — `.env` в CRLF,
хеш был посчитан от значения с хвостовым `\r`, а последующая перезапись файла в LF значения
рассинхронизировала. Починено `trim` в `src/config.js` — важно не только для пароля: ключ API
с `\r` давал бы загадочный 401 от провайдера.

Две грабли, решённые по ходу:
1. `node --watch` не видит правки через bind-mount Docker Desktop на Windows (inotify не

2. `TZ=Europe/Moscow` на alpine игнорируется без пакета `tzdata`, контейнер жил в UTC. Критично
   для проекта: `post_at` в postmypost требует `+03:00`, расписание задаётся в часах. Поставили
   `tzdata`, `date` в обоих контейнерах отдаёт MSK.

Заложено на будущие этапы: `src/lib/http-client.js` (ретраи, бэкофф, `Retry-After`) — общая
обвязка для firecrawl/openrouter/kie.ai/postmypost; контрольные суммы в раннере миграций;

## Протокол обновления

**При старте сессии**:
1. Прочитать этот файл.
2. `git tag -l "stage-*"` и сверить с колонкой «Закрывающий тег». Тег без записи в таблице = таблица устарела, обновить.
3. `git log --oneline -10` — что менялось последним.
4. Только после этого приступать к работе.

**При взятии этапа в работу**:
1. Обновить «Текущий этап» и «Активная работа».
2. Статус 🚧 в таблице.
3. Закоммитить отдельно: `chore(status): start stage N`.

**При закрытии этапа**:
1. Убедиться, что все чекбоксы в `07_ROADMAP.md` отмечены `[x]` и реально проверены человеком.
2. Создать тег: `git tag stage-N-done -m "<описание>"`.
3. В таблице: ✅, «Закрывающий тег», «Последний коммит» (`git rev-parse --short HEAD`), «Дата закрытия».
4. Добавить запись в «Историю закрытий».
5. Указать новый «Текущий этап» и «Следующий шаг».
6. Закоммитить: `chore(status): close stage N`.

**Если этап заблокирован**:
1. Статус ⏸ в таблице.
2. В «Известные блокеры»: что блокирует, кого ждём, что нужно для разблокировки.
