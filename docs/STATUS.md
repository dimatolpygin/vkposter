## Активная работа

**Этап**: 1 — Схема БД + вход в панель, в работе.
**Ветка**: `dev` (git-remote появится на этапе 12, до этого работаем локально)
**Сводка задач**: миграция прикладных таблиц (sources, articles, posts, publications, groups,
settings, runs, users), сид 6 источников из брифа, вход по паролю с сессией в cookie,
выход, смена пароля с инвалидацией сессий, каркас UI панели с пустыми разделами.
**Как верифицируем**: вход/выход/смена пароля руками в браузере; старая сессия в другом
браузере разлогинена после смены пароля; `\dt` показывает таблицы; SQL по `sources` даёт 6 строк.

## Решения, зафиксированные на бутстрапе

- **Админка — один аккаунт** (админ = клиент), все разделы доступны. Обязательна завершённая
  логика доступа: вход → выход → смена пароля с инвалидацией сессий.
- **Промты хранятся в БД** и правятся в панели с версиями. Сид `post_prompt` — реальный промт
  клиента, копия в `docs/prompts/post_prompt.seed.txt`.
- **Redis не берём**: сервер 2 ядра / 2 ГБ, блокировки прогонов и очередь держим в Postgres
  (advisory locks + таблица задач).
- **Картинки храним у себя** (`/media` volume, отдаём по https домена). Временный URL от kie.ai
  в postmypost не отдаём — истекает до отложенной публикации.
- **Git**: свой репозиторий внутри `vkposter`, ветка `dev`. Папка вложена в чужой репо —
  в родительский корень не коммитим. **Remote (GitHub) создаётся на этапе 12** вместе с
  автодеплоем — до этого коммиты только локальные, `git push` не делаем.

`{"db":"ok","migrations":{"версия":"0001_bootstrap","применено":1}}`. Автосборка проверена
сбросом uptime 22 → 10 сек при правке `src/` (в логе `restarting due to changes`).
Идемпотентность миграций: после рестарта — «Новых миграций нет», в `schema_migrations` одна
строка, `app_meta.boot_count` = 7. Логи на русском с `rid` в каждой строке. Ошибка внешнего
запроса (`/_debug/http?status=503`) залогировала статус, тело ответа и `rid`, ретрай сработал.

Две грабли, решённые по ходу:
1. `node --watch` не видит правки через bind-mount Docker Desktop на Windows (inotify не
   пробрасывается) → перешли на `nodemon --legacy-watch` (polling).
2. `TZ=Europe/Moscow` на alpine игнорируется без пакета `tzdata`, контейнер жил в UTC. Критично
   для проекта: `post_at` в postmypost требует `+03:00`, расписание задаётся в часах. Поставили
   `tzdata`, `date` в обоих контейнерах отдаёт MSK.

Заложено на будущие этапы: `src/lib/http-client.js` (ретраи, бэкофф, `Retry-After`) — общая
обвязка для firecrawl/openrouter/kie.ai/postmypost; контрольные суммы в раннере миграций;
`request-id` через AsyncLocalStorage.

## Протокол обновления

**При старте сессии**:
1. Прочитать этот файл.
2. `git tag -l "stage-*"` и сверить с колонкой «Закрывающий тег». Тег без записи в таблице = таблица устарела, обновить.
3. `git log --oneline -10` — что менялось последним.
4. Только после этого приступать к работе.

**При взятии этапа в работу**:
1. Обновить «Текущий этап» и «Активная работа».
2. Статус 🚧 в таблице.
3. Закоммитить отдельно: `chore(status): start stage N`.

**При закрытии этапа**:
1. Убедиться, что все чекбоксы в `07_ROADMAP.md` отмечены `[x]` и реально проверены человеком.
2. Создать тег: `git tag stage-N-done -m "<описание>"`.
3. В таблице: ✅, «Закрывающий тег», «Последний коммит» (`git rev-parse --short HEAD`), «Дата закрытия».
4. Добавить запись в «Историю закрытий».
5. Указать новый «Текущий этап» и «Следующий шаг».
6. Закоммитить: `chore(status): close stage N`.

**Если этап заблокирован**:
1. Статус ⏸ в таблице.
2. В «Известные блокеры»: что блокирует, кого ждём, что нужно для разблокировки.
